# Встроенная библиотека Roblox-ассетов Elio

## Что добавлено
5515 уникальных записей: **5228 TextureId и 287 MeshId**. У каждой — исходное название, тип, источник и категории. У текстур сохранены доступные параметры flipbook/разрешения и авторские подписи; у мешей — парные текстуры, если они указаны в источнике. Повторы объединяются по `(тип, ID)`, разные названия и параметры сохраняются как варианты, а не затирают друг друга.

Это локальная справочная база, поставляемая с расширением, а не личная память проекта. В контекст ИИ попадают только результаты поиска, не весь файл. Скачивать/открывать плагины для поиска не требуется.

## Как пользоваться
После сборки обновить приложение и папку `elio-Extension` из одного комплекта, перезагрузить расширение и вкладку с ИИ. В режиме Roblox агент получает инструмент **elio_asset_library**:

- `{"action":"search","query":"текстура огня","kind":"texture","limit":12}`
- `{"action":"search","category":"impact","layout":"4x4"}`
- `{"action":"search","query":"meteor","kind":"mesh"}`
- `{"action":"get","key":"mesh:1290033"}` — исходная запись, парная текстура, источник, инструкция применения.
- `{"action":"stats"}` — размер базы и категории.
- `{"action":"guide"}` — правила использования ID.

Запрос пользователя: «Собери огненный удар из встроенной библиотеки». Агент сначала ищет здесь, получает точные ID, затем создаёт объекты через существующие инструменты Studio. Поиск только читает данные; он сам ничего не вставляет. Full PC access для этого поиска не нужен. Явно выбранный пользователем плагин остаётся приоритетным.

Поиск поддерживает английские названия и русские ключевые слова: огонь, дым, удар, взрыв, молния, вода, круг, кольцо, звезда, свечение, ветер, разрез, луч, шлейф, метеор, монета, меч, пыль и др. Несколько содержательных слов соединяются условием AND; при нулевой выдаче можно упростить запрос. Это словарь алиасов, не семантическое распознавание изображений. Есть фильтры kind/category/source/layout, пагинация, максимум 30 записей в ответе.

## Источники и права
1. **OpenVFX**: https://github.com/Bloodhundur/OpenVFX
   Данные: `plugin_folder/VFXJSON.luau`, JSON внутри текстовой обёртки. README разрешает использовать, дополнять и менять библиотеку. В Elio включены только метаданные ID/названий/параметров, не код плагина и не файлы изображений. Каталог Meshes у этого источника пуст; он не выдаётся за библиотеку мешей.
2. **Porky8211, «teh Stash of IDs»**, RobloxForum: https://www.robloxforum.com/threads/110388/
   Именованные MeshId и TextureId, включая парные поверхности. Это преимущественно предметы/формы, а не 160 готовых VFX. Типы и названия сообщены автором списка, не подтверждены API для каждой записи. Неоднозначные дополнительные ID в скобках не извлекаются автоматически.

Исходные названия сохранены, описания внешнего вида не придуманы. Права и доступность каждого Roblox-ассета проверяются отдельно при использовании; открытый список ID не является лицензией на все указанные работы. Статус availability=not_checked — не ошибка и не подтверждение загрузки. Известные подписи Credits сохранены. ID моделей не подменяют raw MeshId. Текстуры поверхности меша отделены категорией reference_props/usage mesh_surface от VFX-текстур. При несовместимом разрешении нельзя принудительно обещать native flipbook. Закрытые каталоги QP2/VFX Studio не копировались.

## Реализация
- `core/asset-library/catalog.json` — объединённые данные и происхождение.
- `core/asset-library.js` — read-only движок поиска.
- `background.js` — ленивое чтение локального ресурса и кэш, без сетевого запроса к каталогам во время работы.
- `core/main.js` — объявление инструмента, диспетчеризация и краткая инструкция ИИ.
- Те же ресурсы зеркалированы в `elio-Extension`. JSON входит в build_id через существующий stamp_build.py. Изменений Rust/native маршрутов для поиска не потребовалось.
- `test-asset-library.cjs` включён в Build-Windows.ps1 перед остальными регрессиями.
- `tools/import_asset_catalogs.py --openvfx VFXJSON.luau --forum-text first-post.txt` воспроизводит объединение из сохранённого публичного JSON и plain-text первого сообщения. Luau не исполняется. После обновления данных необходимо синхронизировать JSON в elio-Extension и обновить проверяемые количества теста.

Сборка исходников: `./Build-Windows.ps1` через существующий Windows workflow. Исправления UTF-8/cp1252, LF/CRLF, карточек ошибок, Stop и desktop-автоматизации сохранены.

## Расширение библиотеки: +808 записей
Добавлено **681 TextureId и 127 MeshId**. Предыдущие записи сохранены, дубли объединены.

Новые источники:
- DocsFoxr/Textures_VFX_Roblox (`Particles.share`): 445 записей обработаны, имена и тип Image (AssetTypeId=1) сверены через официальный публичный `economy.roblox.com/v2/assets/ID/details`. Сохранены настройки animate/typeflipbook, creator и сообщённый IsPublicDomain; последний не подменяет проверку прав. https://github.com/DocsFoxr/Textures_VFX_Roblox
- Pew / pewpewagent: открытый Mesh Flipbook Pack. Из RBXM прочитаны 311 экземпляров, 267 экземпляров с ресурсными свойствами и 7 уникальных MeshId. Уникальные ID объединены; сохранены исходные пути и 11 последовательностей отдельных кадров. Скрипты не запускались, исходники runtime не включены. https://devforum.roblox.com/t/open-source-mesh-flipbook-pack/3635032/11
- Bloxodes: первые 120 записей публичного списка мешей (страницы 1–3), авторы, поверхности и ссылки на Creator Store. Это предметы/персонажи/формы, а не 120 готовых VFX. Listing AssetId и raw MeshId хранятся раздельно. Весь каталог из 1000 записей не заявляется скачанным. https://bloxodes.com/catalog/roblox-mesh-ids

Новые команды/фильтры:
- `{"action":"search","kind":"mesh","category":"mesh_flipbook"}`
- `{"action":"get","key":"mesh:99306099992330"}` — mesh кольцевой ударной волны, доступные frame_sequences и кадры в порядке frame_index.
- `{"action":"search","sequence":"MeshFlipbooks/V1/Shockwaves/Ring/Smooth/Textures/Images","limit":30}`
- layout=`SeparateFrames` означает **отдельные изображения для mesh/decal-анимации**, не Grid4x4 одного ParticleEmitter. `get` возвращает максимум 64 кадра выбранной последовательности; для длинных используется поиск с пагинацией. При нескольких frame_sequences можно передать sequence в get.

`core/asset-library/supplement.json` хранит новые нормализованные метаданные с источниками. `python tools/merge_asset_library.py` повторно объединяет их без дублей (идемпотентно) и синхронизирует итоговый каталог в расширение. Импортёр базовых OpenVFX/Forum данных теперь автоматически применяет supplement, поэтому пересборка базы не удалит новые записи. При обновлении supplement синхронизировать и его копию в расширение.

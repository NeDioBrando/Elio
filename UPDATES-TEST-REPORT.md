> Исторический отчёт о первоначальном обновляторе 1.0.0. Текущая версия — Elio 1.0.1; новый адрес — NeDioBrando/Elio. Актуальные проверки и ограничения: ELIO-TEST-REPORT.md.

# Проверки системы обновлений — первый релиз v1 (1.0.0)

## Выполнено в Linux

- Полный `cargo test --locked --manifest-path agent/Cargo.toml`: 3 библиотечных + 127 тестов приложения успешно; один отдельный тест проигнорирован. Включены новые проверки числовых версий, строгого формата GitHub asset, защиты от параллельного инструмента и учёта активности нескольких браузеров.
- `node test-elio-audit.cjs`: аудит форка, идентичности runtime-копий расширения, проверка синтаксиса JS.
- `node test-desktop-chat.cjs`: регрессия контрактов нативного чата.
- `node test-updates.cjs`: версии, Outdated, ошибки проверки, прогресс, перезагрузка расширения, общие UI/transport-контракты.
- `node test-desktop-chat-ui.cjs`: нативная HTML-страница в Chromium с mock-мостом; сценарии чата, безопасное отображение, ошибки отправки, восстановление и узкий экран.
- `node test-update-ui.cjs`: тот же реальный HTML/CSS/JS с mock-мостом; кнопка обновления, состояние загрузки, ошибка сети, плавающая панель сайта, перезагрузка расширения, экран 390 px. Снимки проверены визуально, после исправления компоновки и устаревшего текста статуса выполнен повторный прогон.
- Парсер PowerShell 7: `apply-update.ps1`, Windows helper test и `Build-Windows.ps1` без синтаксических ошибок. Это не исполнение в Windows PowerShell 5.1.
- `git diff --check`; проверка целостности исходного ZIP.

## Добавлено для Windows, здесь не выполнено

`test-updater-helper.ps1` запускается сборочным сценарием через Windows PowerShell 5.1 до упаковки (для .NET Framework тестовых EXE). Создаёт временные тестовые EXE и проверяет успешную установку, неверный SHA-256, несовпадающий manifest, traversal в ZIP и восстановление после неудачного запуска. Проверяет сохранность пользовательского config. Полные Rust-тесты также входят в Windows workflow.

Ни Windows workflow, ни эти helper-интеграционные тесты, ни реальный Windows EXE/GUI в Linux не запускались. PowerShell parser, Linux Rust-тесты и UI-моки не доказывают работу обновления на компьютере пользователя. В этом пакете нет собранного Windows EXE.

## Что обязательно проверить перед публичным релизом

1. Собрать 1.0.0 на Windows x64 и установить в отдельную тестовую папку; расширение загрузить из неё.
2. Подготовить и проверить новую версию. На тестовом канале проверить GitHub release с точным именем ZIP и digest; для отдельного тестового репозитория нужен отдельный build с изменённой константой, произвольный feed UI не принимает.
3. Увидеть одинаковый Outdated в приложении, popup и странице ИИ; запустить обновление с каждого интерфейса в отдельных прогонах.
4. Проверить остановку активных задач, прогресс, недоступную сеть, блокировку/недоступность папки, закрытие приложения и запуск новой версии, сохранность настроек.
5. Проверить перезагрузку расширения/вкладок и отсутствие дальнейшего Outdated при совпадающих версиях; проверить откат при старте неисправного тестового EXE.
6. Проверить реальные Chromium, Roblox Studio, Blender и сторонние MCP-процессы. В текущем UI-прогоне использовались моки, не аккаунты ИИ и не настоящая сцена.

Независимой подписи пакета нет: доверие GitHub-аккаунту, HTTPS и digest API. Ограничения и инструкция публикации — UPDATES-RU.md. Предыдущие отчёты сохраняют историческое описание прежних ревизий.

## Перенумерация первого публичного релиза

Техническая версия синхронизирована как 1.0.0 в Cargo.toml, Cargo.lock и обоих manifest. Имя публичного релиза — Elio v1, тег v1.0.0. После перенумерации повторно выполнены аудит расширения, JS-тесты чата и обновлений, полный Rust-прогон и проверка исходного ZIP. Тестовые фикстуры 1.0.1/1.0.2 сохранены как примеры перехода и не задают версию продукта. Windows-сборка и реальная установка по-прежнему не выполнены.

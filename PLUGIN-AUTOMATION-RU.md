# Elio 1.0.1 — управление интерфейсом плагинов Studio

## Что изменено

Раньше `plugin_list` / `plugin_inspect` только читали дерево UI. Они не могли нажать кнопку или подтвердить, что пользователь видит карточку. Эти инструменты сохранены; точная адресация `surface_title` не удалена.

Добавлены **нативные инструменты Windows**, доступные в каталоге ROBLOXSCRIPT:

- `studio_ui_snapshot`: PNG настоящих экранных пикселей клиентской области главного окна Studio и до 300 посещённых элементов Windows UI Automation. `focus=true` пытается вывести Studio на передний план. Возвращает `snapshot_id`, относительные координаты и доступные `element_id`. UI Automation может не видеть нарисованные Roblox/Qt-контролы — тогда используются координаты с реального снимка.
- `studio_ui_action`: одно действие `click`, `type_text`, `key` или `scroll`. Текст поступает в фиксированный PowerShell/C#-мост как JSON через stdin, не исполняется как PowerShell. Ввод выполняется через Windows SendInput; буфер обмена не используется. Нет выдуманного plugin API или подделки Roblox-сигналов.

Так агент может открыть наблюдаемую кнопку на вкладке Plugins, набрать поиск, выбрать карточку и нажать наблюдаемое Insert/Replace, после чего проверить фактическое изменение объекта. Это **инструменты управления с инструкциями агенту**, а не отдельные жёстко зашитые сценарии/драйверы внутренних каталогов четырёх плагинов. Расположение кнопок не захардкожено. Для Emitter2D не предполагается отдельное окно редактора: используются его реальные кнопки toolbar.

## Использование после GitHub-сборки

1. Заменить Elio и расширение файлами из нового Windows-артефакта; перезапустить Elio, перезагрузить вкладку ассистента.
2. Разрешить **Full PC access** в Elio, только если нужен desktop-ввод. Исходник не включает это разрешение автоматически. В sandbox инструменты объяснят отказ.
3. Оставить ровно один запущенный процесс Studio и один подключённый MCP-сеанс. Это намеренное ограничение: существующий MCP не предоставляет надёжного соответствия studio_id ↔ Windows PID. Автоматически закрывать другие проекты нельзя.
4. Использовать явный актуальный `studio_id`. Плавающее окно плагина нужно закрепить внутри главного окна Studio. Окно должно полностью находиться на экране, не быть свёрнутым; не перекрывать его и не печатать параллельно действиям агента.
5. Агент получает `studio_ui_snapshot`, смотрит PNG, выполняет **один** `studio_ui_action`, затем получает новый снимок / читает DataModel. Для поля поиска: клик → новый снимок → CTRL+A → новый снимок → type_text → новый снимок и проверка результатов.

Координаты относятся к **PNG клиентской области**, а не всему рабочему столу и не Roblox AbsolutePosition. Клиентская область включает Studio ribbon/toolbar, но не системную рамку окна. UIA-список не заменяет визуальную проверку. Снимки могут содержать перекрывающие окна; hit-test запрещает ввод сквозь чужие окна.

## Ограничения и защита

- Только Windows; Linux/macOS возвращают явный отказ, не изображают успешную автоматизацию.
- Разрешение Full PC, read-only и разрешённые папки проверяются и не отменяются. Folder-restricted mode блокирует desktop-мост; read-only запрещает ввод.
- Один непрозрачный случайный ID снимка, срок 45 секунд. Снимок расходуется при попытке действия, включая ошибки в параметрах. Ввод сериализован, без автоповтора.
- Перед вводом проверяются процесс RobloxStudioBeta.exe, время старта, HWND, заголовок, геометрия, foreground/enabled, принадлежность точки главному окну; для текста — текущий фокус, для element_id — повторная проверка UIA-идентичности/названия/типа. Изменения динамического UI не могут быть полностью обнаружены: агент обязан проверять свежий снимок и результат каждого действия.
- Нажатые пользователем модификаторы/кнопки мыши блокируют ввод. Нет произвольных сочетаний клавиш, shell-команд или доступа к clipboard. Текст ограничен 512 UTF-16 units без управляющих символов; прокрутка — 1–5 шагов.
- PowerShell — отдельный дочерний процесс с kill-on-drop/25-секундным таймаутом. Stop прерывает ожидание; уже отправленный ввод отменить невозможно. При ошибке возможен частичный результат: новый снимок, не слепой повтор.
- Desktop-действия отмечаются как внешние операции без обещания полного Studio Undo. Существующий журнал задач/Stop сохранён.
- Инструкции запрещают автоматически разрешать Trust Asset, установку/обновление клиента, script permissions, upload/publish. Это отдельные решения пользователя, не этап обхода ошибки.
- Импорт, лицензии и разрешения ассетов не обходятся. Платные движки/каталоги не включены в исходник. Проекты пользователя этим изменением не редактировались.

`plugin_inspect` теперь дополнительно сообщает `ancestor_hidden`, `hidden_by` и `desktop_visibility=unverified`. Даже `ancestor_hidden=false` НЕ доказывает видимость на экране: clipping/перекрытия/состояние окна проверяются по реальному снимку.

## Что проверено / что ещё не доказано

Локально: Rust validation/policy/session tests, полный синтаксический разбор PowerShell и компиляция встроенного C#, размер INPUT, маршрутизация нативных инструментов, сохранение каталога при polling, JS/skills parity, полные Luau-блоки и export-inspector fixtures. Windows-сборка GitHub запускает эти проверки до компиляции/упаковки.

**Не выполнено на пользовательском Windows:** реальный SendInput в Studio, качество PNG при DPI/нескольких мониторах, доступность UIA у конкретной версии Studio, полный проход поиск → выбор → Insert/Replace у QP2/VFX Studio, toolbar Emitter2D/Eclipse, визуальная приёмка. Локальные тесты не объявляются доказательством этих действий. Старые ручные проверки из чата не являются тестом нового моста.

Это полный исходник для существующего `.github/workflows/build-windows.yml` → **Run workflow**. Локальный Windows EXE не прилагается; версия продукта остаётся 1.0.1, source build identity изменяется.

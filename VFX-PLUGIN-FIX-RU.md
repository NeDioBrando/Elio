# VFX Studio — исправление generated Luau и диагностики UI

Версия продукта: Elio 1.0.1. Полные исходники поверх Memory/Performance Audit; Eclipse, Oriveo, Figma и память проекта сохранены. Сборка по прежнему GitHub Actions / Build-Windows.ps1.

## Что подтвердилось
Предыдущий production-генератор plugin_list воспроизвёл ТОЧНО ошибку `:65: Malformed string; did you forget to finish it?` в настоящем компиляторе Luau (luau-web 1.5.1). Это ошибка Elio, не доказательство неисправности или отключения VFX Studio.

Причины в общей библиотеке core/studio_skills.js:
1. Внутри Luau short string находился физический перенос строки. Кроме того, обычный JavaScript template literal превращал остальные `\n` в физические переносы Luau-строк. Исправлены исходная строка и сохранение экранирования через String.raw.
2. После устранения первой ошибки компилятор выявил два незакрытых блока: alias warm_night и ветку Forge component. Они исправлены: общий шаблон должен компилироваться даже при вызове совершенно другой команды plugin_list.
3. Новый тест компиляции всех ветвей выявил недопустимые для Luau `\u25b2` / `\u2026` в отдельном генераторе card inventory. Заменены реальными Unicode-символами.

Предыдущие VFX-тесты проверяли routing и самостоятельный exported-asset inspector, а не полный generated chunk plugin_list. Поэтому такой дефект они пропустили. Теперь тест компилирует полный production-результат каждой из 34 команд и запускает plugin_list/plugin_inspect в runtime fixtures; этот тест добавлен в существующую Windows-сборку.

## Диагностика и поиск доступного UI
- plugin_list возвращает текущие доступные поверхности, Title, Enabled/Visible и другие доступные скалярные поля, точные path_segments, access warnings и флаг read_only. Лимит 200 поверхностей.
- Отсутствие PluginGuiService/PluginDebugService или отказ доступа больше не превращается в молчаливую пустоту без объяснения. Нулевой результат НЕ равен «плагин выключен/не установлен».
- plugin_inspect принимает свежий path_segments (правильно обрабатывает точки, пробелы и кавычки в именах) или dotted path. Дубликаты имён отвергаются как неоднозначность; произвольный старый путь не подменяется первым похожим объектом.
- Читает вложенное дерево с Title/Text/Image/Visible/Enabled/Active/Interactable, без чтения Source, require, кликов или изменения свойств.
- query — буквальный фильтр по прочитанным именам, заголовкам, текстам и image IDs. Скрытые элементы могут присутствовать в дереве с Visible=false: это НЕ доказательство доступности для клика. Английские буквы сравниваются без регистра; полноценный Unicode case-folding не заявляется.
- max_nodes: 1–400 (по умолчанию 200), max_depth: 0–12 (по умолчанию 6). При недочитанном дереве/отказе доступа возвращается truncated/warnings; для продолжения исследуют более узкий точный путь. Данные свойств и результаты ограничены, это не полная выгрузка плагина.
- JSON arguments вставляются callback-заменой, чтобы `$&` и похожие последовательности не меняли данные. Вложенный args.op не может подменить выбранную маршрутизатором команду.
- Скилл и task-context явно различают чтение UI, настоящий поиск библиотеки и фактический импорт.

## ВАЖНО: что не было доказано и не обещается
Это НЕ новый private API VFX Studio и НЕ автоматический импортёр внутреннего каталога.
query у plugin_inspect не вводит текст в поиск плагина, не загружает скрытые страницы библиотеки, не нажимает Import. motion_scan читает уже материализованные DataModel-объекты, не приватную библиотеку плагина. Из thumbnail image ID нельзя делать вывод, что это asset ID целого эффекта.

Для реального поиска/вставки из библиотеки нужны наблюдаемый UI установленного VFX Studio и разрешённые инструменты управления Studio UI, либо один ручной шаг пользователя: вставить/выбрать нужный preset. Затем можно проверить экспорт и безопасно копировать его существующим motion_bundle_copy с source_path. Доказательство копирования экспортированного объекта не является доказательством импорта из приватной библиотеки.

В присланном отчёте импорт ещё не вызывался. Поэтому по нему невозможно установить отдельный баг операции импорта или объявить её починенной. Исправлен подтверждённый блокер plugin_list и улучшен путь диагностики. Нужна проверка новой версии на реальном Studio.

## Проверки
См. VFX-PLUGIN-FIX-RESULTS.json — актуальные результаты именно этого исправления. Остальные отчёты в комплекте относятся к предыдущим этапам.
- Старый код: воспроизведена точная ошибка :65 Malformed string.
- 34 полных generated chunks компилируются.
- 16 runtime fixtures: частичный/недоступный/пустой UI, актуальные и устаревшие пути, точки в именах, дубликаты, вложенные labels/images, скрытые элементы, запросы с Lua-pattern символами, лимиты большого дерева, запрет мутаций и чтения Source, сохранность сериализации и выбранной операции.
- Самостоятельный VFX asset inspector: 31 проверка simulated DataModel.
- Финальный прогон: 31/31 актуальная регрессионная команда, 165 Rust-тестов (ещё 1 ignored), Linux debug build, реальный локальный skill API; 68 JS-файлов проверены на синтаксис и parity. Windows build здесь не выполнялся.
- Дополнительно проверенный исторический test-v115.js имеет те же 13 устаревших failures и в предыдущем архиве; он не входит в текущую Windows-сборку. Это не новый регресс и не записано как успешный тест.
- Existing motion Luau fixtures проверяют копирование экспортированного источника, fidelity, replay, runtime и сохранность исходника. Это не живой VFX Studio.
- Архив содержит тесты и SHA256-манифест. В нём нет node_modules, target, пользовательских эффектов, приватной библиотеки или нового exe.

## Проверка на ПК
1. Собрать через обычный GitHub workflow; обновить и приложение, и расширение из того же комплекта, перезагрузить расширение/страницу чата.
2. В Edit mode проверить plugin_list: не должно быть `Malformed string`. Пустоту/отказы трактовать по предупреждениям, а не как выключенный плагин.
3. Открыть VFX Studio, заново выполнить plugin_list и plugin_inspect по свежим path_segments. Проверить реальные заголовки, labels/images и truncated.
4. Только при доступных инструментах Studio UI выполнить ограниченный поиск/вставку, сравнив состояние до/после. Иначе пользователь вставляет один preset вручную.
5. Подтвердить появившиеся объекты, проверить их asset IDs/attachments/scripts, скопировать owned template и проверить внешний вид. Не повторять неоднозначную мутацию вслепую.

Если обнаружится следующий сбой, нужны точное имя команды, её аргументы без секретов и полный ответ/ошибка. Скриншот свежего VFX Studio поможет проверить реальный UI, но не заменяет receipt вставки.

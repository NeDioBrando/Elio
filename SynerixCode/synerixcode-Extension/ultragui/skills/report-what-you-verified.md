# report-what-you-verified

Use this user-provided reference only when it helps the current project request. Adapt paths, assets, style and APIs to the actual project and available synerixcode tools: use the official Roblox docs tools listed by list_commands where it names fetch_roblox_doc, and the Toolbox/Creator Store tools listed by list_commands where it names search_creator_store or insert_from_creator_store. synerixcode can run Studio tools, so verify with them instead of waiting for the user. The current user scope takes priority. Keep working features. Do not impose extra search loops or ask the user to continue after every component. Use actual tests when tools permit; report what remains untested.

When relevant: the end of every UltraGUI task.

Finish with:
- Screens: each one, marked done, stuck (with the reason), or not started.
- Style and archetype used, or "plain".
- References: each file, link or name you used, and what you took from it.
- Toolbox: each asset's name, creator, asset ID and what changed, or "none".
- Docs read: each docs address you fetched, and what it confirmed. List any you could not fetch.
- Checked by numbers and by reading: the check-cycle results, the syntax checks, and the cycles each item took.
- Not checked: anything that needs a person in play, a link you could not open, an asset ID you
  could not confirm, or a licence you could not read.
Do not say "tested" or "looks good". Say what was measured, what was read, and what was not run.

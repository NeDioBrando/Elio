# Desktop Chat — доработка SynerixCode

База: `NeDioBrando/SynerixCode`, commit `158359b52a80549f6325ec55b40dc28e0a239674`.
Изменения подготовлены 18 октября 2026. Лицензия GPL-3.0-or-later и исходная атрибуция сохранены.

## Что добавлено

В существующее окно Rust + Wry/WebView2 добавлена начальная вкладка **Chat**. Отдельный Electron, API-ключ модели или второй браузер не требуются.

- Чтение пользовательских сообщений и ответов ИИ через существующий интерфейс `RSProvider`.
- Обновление текста незавершённого ответа примерно раз в секунду при видимом окне приложения. Это опрос снимков DOM, не прямой поток токенов от сервера модели.
- Поле ввода: Enter отправляет, Shift+Enter вставляет строку; IME-композиция не вызывает отправку.
- Запуск агента и остановка через существующий контроллер расширения.
- Закрепление вкладки в текущей браузерной сессии. После этого можно переключать другие вкладки; браузер остаётся запущенным.
- Раздельные черновики в памяти приложения для пары браузер/вкладка/чат. При закрытии приложения эти черновики не сохраняются на диск.
- Сохранение текста при ошибке подтверждения. Нет автоматического повтора отправки; ручной повтор использует прежний request ID.
- Проверка назначения на стороне агента, background worker и content script: смена чата не должна перенаправлять запрос в другой разговор.
- Текст модели не исполняется как HTML; блоки с тройными обратными кавычками выделяются как код. Полный Markdown, вложения и интерактивные виджеты сайтов в этом UI не реализованы.

## Как собрать и запустить на Windows

1. Используйте эту обновлённую папку исходников целиком. Старый exe не содержит нового UI.
2. Требования остаются прежними: Rust MSVC, Visual Studio Build Tools/Windows SDK, Python, Node, WebView2. Подробности — в `README-RU.md`.
3. Выполните из PowerShell:

```powershell
.\Build-Windows.ps1
```

4. Распакуйте полученный `dist\synerixcode-v1-Windows-x64.zip` в новую папку и загрузите/обновите расширение из **synerixcode-Extension** через `chrome://extensions` или `edge://extensions`.
5. Запустите новый `synerixcode.exe`. Откройте поддерживаемый чат в браузере и войдите в свой аккаунт обычным способом. После обновления расширения перезагрузите вкладку чата.
6. В приложении откройте **Chat**, нажмите **Закрепить вкладку**, затем **Запустить агента**. Когда агент готов, отправляйте запросы через поле приложения. Режим RobloxScript/AgentScript и остальные настройки по-прежнему доступны на существующих страницах приложения.
7. Браузер можно свернуть, но не закрывать. Если нужны вход, CAPTCHA, выбор модели, новый разговор или функции сайта, которых нет в UI, используйте браузер. После навигации в другой разговор проверьте назначение перед отправкой.

В этой выдаче нет собранного или проверенного Windows exe. Исходные архивы PlazCode из репозитория не являются новой сборкой и не должны использоваться вместо неё.

## Архитектура

```text
Native window (existing Wry/WebView2)
  └─ desktop/chat.js: UI + transport contract
       └─ authorized HTTP /api/desktop/agent
            └─ Rust acknowledgement/event channel
                 └─ extension background: browser identity + pinned tab
                      └─ core/main.js: chat-read / existing task-send
                           └─ existing RSProvider
                                └─ AI website

Tool execution: existing agent loop → native bridge → Roblox Studio / Blender
```

`desktop/chat.js` не обращается к `chrome.*` и DOM сайта ИИ. Контракт транспорта: `read(control, revision)`, `send(control, text, requestId)`, `start(control)`, `stop(control)`, `pin(control, enabled)`. UI получает состояние возможностей отдельно через существующий desktop state. Транспорт выделен функцией `createTransport(api)`.

`chat-read` возвращает `chat`, `provider`, `revision`, `history`, `omitted`, `generating` или `not_modified`. Ревизия включает идентификатор жизни content script, поэтому перезагрузка вкладки не переиспользует старую ревизию. История ограничена 300 сообщениями и 160 000 символами; весь ранее захваченный текст продолжает использовать существующий механизм архивирования. Старые сообщения, которые сайт не загрузил или виртуализировал до подключения, могут отсутствовать.

`chat-pin` обслуживается background worker; tab ID сохраняется в `chrome.storage.session`. Закрытие закреплённой вкладки сбрасывает закрепление. Другой браузер не вытесняет живую закреплённую сессию одним получением фокуса. Для смены браузера сначала снимите закрепление.

Заголовок Authorization, существующая проверка origin и проверка pairing не отключаются. Новых открытых endpoint для истории не добавлено. Текст чата поступает через существующий авторизованный RPC; ключ не передаётся в URL.

## Lightpanda: граница миграции

**Поддержка Lightpanda ещё не реализована и не проверена.** Сейчас исполняется Chromium-расширение, использующее Chrome API. Отделение транспорта уменьшает объём будущей миграции, но не превращает расширение в совместимое с Lightpanda автоматически.

Следующий шаг — отдельный runtime-адаптер, управляющий браузером через поддерживаемый им протокол автоматизации и выдающий те же снимки, возможности и подтверждения. В него потребуется перенести управление вкладкой/сессией, ввод, чтение DOM, обнаружение генерации, идемпотентность и жизненный цикл agent loop. Необходимо отдельно проверить работу каждого провайдера, авторизацию, особенности DOM и загрузку вложений. Существующий UI можно оставить; WebView2 в окне приложения и браузерный движок веб-ИИ — разные компоненты.

## Известные ограничения

- Сначала запускается агент, затем отправляется запрос. Это сознательное использование существующего agent loop, а не новый независимый режим общения без инструментария.
- Ответ `task-send: ok` означает принятие задания расширением, а не подтверждённую доставку сайту или успешное исполнение Studio. Реальный результат смотрите в чате и существующих Activity/Terminal.
- Дедупликация ручного повтора использует существующий in-memory кэш расширения. После перезагрузки вкладки/расширения гарантии exactly-once нет: сначала проверьте историю, не повторяйте сомнительный запрос вслепую.
- При фоновой работе задержки могут быть больше секунды из-за поведения браузера и сайта. Нет обещания работы при закрытом браузере, спящем компьютере или потере сессии.
- Нет автологина, обхода защит сайтов, эмуляции аккаунтов или переноса cookies.
- Живой прогон с вашим аккаунтом, Roblox Studio/Blender и Windows WebView2 в этой среде не выполнен.

## Проверки

```bash
node test-synerixcode.cjs
node test-desktop-chat.cjs
cargo check --locked --manifest-path agent/Cargo.toml
cargo test --locked --manifest-path agent/Cargo.toml
```

Опциональный UI-тест требует Playwright и локальный Chromium:

```bash
npm install --no-save playwright
CHROMIUM_PATH=/path/to/chromium node test-desktop-chat-ui.cjs
```

На Windows задайте `$env:CHROMIUM_PATH` вместо синтаксиса переменной Unix. UI-тест использует исключительно подставной локальный HTTP-транспорт; реальные аккаунты не подключаются. Снимки записываются в каталог `SYNERIXCODE_TEST_OUTPUT`, если он указан, иначе в текущий каталог. Статус текущего прогона — в `DESKTOP-CHAT-TEST-REPORT.md`.

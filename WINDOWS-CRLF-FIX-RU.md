# Elio 1.0.1 — Windows LF/CRLF build fix

## Причина

Проверка `tools/test_studio_desktop_contract.py` сравнивала SHA256 сырых байтов `core/config.js` с хешем LF-версии. Git на Windows может выдать тот же текст с CRLF. Одной такой замены достаточно, чтобы воспроизвести присланный `AssertionError`.

## Исправление

- При проверке только этого текстового исходника нормализуется `CRLF -> LF` перед вычислением SHA256.
- Ожидаемый хеш сохранён. Пробелы, BOM и реальные изменения текста не игнорируются.
- `core/config.js` не переписывается и не заменяется.
- SHA256 бинарников, Engram runtime и файлов внутри пакета остаются побайтовыми.
- Добавлен `tools/test_windows_source_newlines.py` и его запуск перед desktop-contract в `Build-Windows.ps1`.

## Проверки

Новый тест создаёт отдельные LF- и CRLF-копии всех файлов, используемых desktop-contract, и запускает настоящий контракт. Оба варианта проходят. В обоих вариантах добавление реального текста в конфигурацию отклоняется именно проверкой хеша. Тест не редактирует исходник проекта.

Дополнительно прошли прежняя регрессия Windows cp1252, Python-синтаксис, Engram runtime checks и 20 тестовых файлов: обработка ошибок/Stop, карточки истории, сохранность прежних функций, генерация Luau плагинов, Eclipse, Oriveo, Figma, память, темы/обновления, Motion и live-audit проверки.

## Использование

Полный исходник включает оба предыдущих исправления: UTF-8 сборки и ошибки/карточки агента. Заменить файлы репозитория содержимым архива, сделать новый commit и запустить новый **Run workflow** для этого commit. В новом журнале перед desktop-contract появятся строки `PASS LF checkout` и `PASS CRLF checkout`.

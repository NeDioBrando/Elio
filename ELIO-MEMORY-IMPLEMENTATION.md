# Elio 1.0.1 — project memory and chat update

## Что сделано

### Память проекта

В боковом меню приложения появился раздел **Memory**. Это локальное хранилище Markdown, а не дополнительный облачный сервис и не обязательная установка Obsidian.

- **Notes**: категории, полнотекстовый поиск, редактор, теги, источник, подтверждения и статус записи.
- **Connections**: граф реальных `[[ссылок]]`, цвета категорий, масштабирование, перемещение, переход к заметке с клавиатуры, скрытие изолированных узлов.
- **Agent context**: просмотр компактной подборки памяти, которую получает агент, с причинами включения записей.
- История изменений, архивирование, восстановление, удаление с подтверждением, импорт и экспорт.
- **Auto memory** отключает автоматические записи агента, но не ручное редактирование пользователем.
- Новые записи появляются в открытом разделе Memory автоматически, без Refresh. Поиск проверяет всё тело заметки, а не только её начало.

Проекты изолированы. Выберите проект в списке; **Active project** возвращает к проекту активного чата. **New project** создаёт/назначает проект текущему чату, если он открыт. Без выбранного чата используется отдельная область Personal. Чат без назначения проекта получает отдельную chat-область, а не память чужого проекта.

На Windows файлы находятся в `%LOCALAPPDATA%\elio\vault\<hash-scope>\notes\`. **Vault location** показывает фактическую папку. История лежит отдельно в `.history`. Файлы содержат YAML-поля и Markdown-текст; идентификаторы и scope необходимо сохранять при внешнем редактировании.

Старые личные заметки и данные Engram не удалены. **Import old notes** копирует подходящие старые заметки в текущую область как unreviewed; исходники остаются нетронутыми. Длинные записи разбиваются на части без разрыва Unicode-символов. Повторный перенос уже импортированных частей не создаёт дубликаты. Экспорт создаёт JSON-пакет с Markdown-файлами; импорт такого пакета сохраняет ID и связи и отказывается затирать конфликтующие записи.

### Для агента

Основной инструмент — `elio_vault`:

1. `context` с запросом задачи: компактная подборка, обычно один вызов вместо чтения всего хранилища.
2. `search` / `read` — детали по необходимости.
3. `save` — только долговременные факты, решения и предпочтения; источник обязателен, для verified нужны ссылки на подтверждения.
4. Правки требуют `id`, `revision` и `etag` из свежего чтения. Устаревшая правка отклоняется; чужие изменения не затираются молча.

Сохранение возвращает короткую квитанцию, а не повторяет всю заметку. Идентичная запись не создаёт новое уведомление. Память передаётся как справочный материал, а не как инструкция, заменяющая актуальную задачу или проверку проекта. Текущие шаги/checkpoints не записываются автоматически как подтверждённые факты.

### Чат и анимация

- Исправлено склеивание абзацев на пути Notion → расширение → встроенный чат. Сохраняются границы абзацев, списков, BR и блоков кода; соседние inline-элементы не получают лишних пробелов.
- Буква e наклоняется к точке, вытягивает «язычок», дрожит, срывается и прокручивается. Точка немного ускользает. Цикл повторяется; текст статуса переливается серым градиентом.
- При `prefers-reduced-motion` анимация отключена.
- После подтверждённой записи появляется уведомление с лампочкой и названием записи. Встроенный чат показывает квитанцию у результата инструмента; расширение — dismissible toast. Ошибка или запись без изменений не выдаются за успешное добавление.

## Как установить

Это **полные исходники**, не готовый Windows EXE.

1. Распаковать в новую папку. Не заменять пользовательскую папку данных Elio и не удалять старую память.
2. На Windows выполнить `./Build-Windows.ps1` по существующей инструкции проекта. Скрипт включает новый контракт памяти и Rust-тесты; затем собирает и упаковывает приложение.
3. Закрыть старый агент, запустить новый EXE и перезагрузить установленное расширение из папки `elio-Extension`. Старый EXE не содержит новый backend/интерфейс.
4. Открыть Memory, выбрать нужный проект. При необходимости вручную перенести старые заметки.

Версия продукта оставлена **1.0.1**. Roblox-сцена в рамках этой работы не менялась. Архив не содержит тестовые заметки, пользовательские данные, зависимости node_modules или собранный Linux-бинарник.

## Проверки и честные ограничения

Точные результаты — в `VAULT-TEST-RESULTS.json`.

Rust: **139 passed, 0 failed, 1 ignored** (3 library + 136 binary). Общий JS-прогон: **162 из 186 прошли**; оставшиеся 24 неуспешны и на чистом исходном commit. Сквозной native + Chromium тест прошёл отдельно от этого набора.

Проверены настоящий Rust API и настоящий Chromium с временным профилем: авторизация/origin, сохранение и перезапуск, история, параллельный конфликт правок, разделение проектов, автоматическая память OFF, импорт/экспорт, граф и backlinks, безопасный показ HTML, сохранение черновика, узкое окно и светлая тема, живое обновление и поиск в конце заметки.

Отдельные тесты покрывают абзацы, подтверждённые квитанции, компактный ответ сохранения, привязку области расширением, длинный Unicode-импорт, отсутствие дубликатов, паритет папки расширения и восстановление после устаревшего DOM. Новый тест включён в Windows build script.

Тест масштаба: 1000 связанных заметок, Linux debug build, один измеренный прогон: холодный context ≈536 мс, прогретый ≈8,57 мс, подборка 1498 символов. Это не гарантия скорости Windows и не production benchmark.

**Не утверждается, что весь старый репозиторий стал безошибочным.** Общий JS-набор содержит старые несогласованные проверки и сценарии с недоступными окружению зависимостями. Неуспешные сценарии сравнены с чистым исходным commit `d2cfc0d3fa89117729a115a6d9800b3e0fdf08a3`; подробности приложены. Новые обнаруженные регрессии исправлены, старые проверки не отключались ради зелёного отчёта. Изменение identity-scope baseline явно ограничено заказанным новым разделом памяти.

**Нужна пользовательская проверка на Windows:** реальная сборка EXE, WebView2, подключение браузерного расширения к установленному приложению и длинный живой диалог на вашем провайдере. Здесь проверялся Linux backend + Chromium, а не установленный Windows WebView2. Живой Engram runtime отдельно не запускался: новая память от него не зависит, прежний интерфейс сохранён.

## Границы реализации

- Поиск лексический, не embeddings/семантическая модель. Граф основан на явных ссылках, а не на выдуманных связях.
- Source/evidence сохраняются и показываются, но наличие ссылки само по себе не доказывает истинность утверждения. Статус stale есть; автоматического наблюдения за всеми Roblox-скриптами и доказательства устаревания нет.
- Лимиты: 5000 заметок/проект, 32 МБ текущего текста, 64 000 UTF-8 байт на заметку. История хранится дополнительно. UI-граф показывает до 500 заметок с предупреждением об усечении.
- Context: до 8 начальных совпадений, до 12 записей со связанными соседями, обычный бюджет 6000 символов, максимум 12000. Автоматическое предварительное вспоминание использует меньший бюджет 4500.
- Чтение внешнего YAML поддерживает используемые поля, простые списки и CRLF, но не заявляет поддержку всего YAML/всех плагинов Obsidian.
- Заметки не исполняют HTML/JavaScript; symlink-пути заметок отклоняются. Повреждённый файл не удаляется молча — возвращается ошибка для исправления пользователем.

## Исследование и принятые решения

Из Obsidian взяты переносимые Markdown-файлы, свойства, wikilinks и backlinks: данные принадлежат пользователю, индекс можно пересоздать.

- https://obsidian.md/help/data-storage
- https://obsidian.md/help/Editing+and+formatting/Properties
- https://obsidian.md/help/links

Из изученных открытых agent/vault-проектов выбраны полезные инженерные приёмы: машинные схемы и короткие JSON-ответы, ограниченный context seed + один шаг по связям вместо загрузки всего vault, источники/история/статусы и возможность ручной проверки.

- https://github.com/nightisyang/obsidian-cli
- https://github.com/jrcruciani/obsidian-memory-for-ai

Эти проекты — референсы подхода, не доказательство производительности нашей реализации. Реализация Elio собственная; сторонний код из этих репозиториев не копировался. «Идеальная память» не обещается: описаны реально реализованные свойства и проверенные сценарии.

## 1.0.1 source refresh: selected 1.24.21–25 ideas

The backend remains Elio's existing project-scoped, revision/etag-checked Markdown store. Added `audit`, evidence-backed `verify`, `dependencies`/`observed` fingerprints, conservative invalidation after supported checkpoint writes, stale exclusion from both context seeds and linked context, normalized local reference images and a separate Obsidian snapshot export. Export is not bidirectional sync. Evidence is supplied, not independently proven; opaque/external edits still need a fresh observed check. See UPSTREAM-21-25-RU.md for paths, privacy and limitations, and the matching JSON report for actual validation.

# Qwinkle’s Particles 2 — встроенный навык Elio 1.0.1

## Что добавлено
- Отдельный встроенный навык **Qwinkle’s Particles 2 (QP2)** в Skills, с инструкциями и шестью локальными ресурсами. Он добавляется при обновлении каталога, не перезаписывает пользовательские навыки и учитывает явное удаление.
- Прямая просьба использовать QP2 выбирает этот навык независимо от Blender. Прямая просьба VFX Studio не подмешивает QP2. Для общего запроса Roblox VFX доступны оба варианта: агент должен выбрать подходящий установленный инструмент, а не редактировать один эффект двумя плагинами одновременно. Исключение QP2 учитывается. Анимация персонажей остаётся задачей Eclipse/Blender.
- Собственный **read-only Luau-инспектор** уже экспортированного эффекта: проверяет PartIcleProperties, RenderTemplate, внешние ссылки, скрипты/Events, нулевой burst, петли и используемые asset ID. По умолчанию 160 узлов, максимум 400, до 48 000 байт вывода. Он не читает Source, не вызывает require, не меняет trust, не запускает эффект и не изменяет сцену.
- Инструкция по runtime Part_Icles: проверять фактический модуль и версию, различать burst/continuous, ограничивать preview и останавливать свои эффекты без выключения общего движка проекта.
- Предыдущие исправления VFX Studio и навыки Eclipse, Memory, Figma, Oriveo сохранены. Версия продукта остаётся 1.0.1.

## Важная граница
Это интеграция **навыка и диагностики**, не обещание полного автоматического управления приватной библиотекой QP2. plugin_list/plugin_inspect читают доступный UI. Их query не является поиском по всей Inventory и не нажимает Insert. Если доступного инструмента управления Studio UI нет, агент попросит открыть плагин и выбрать/экспортировать нужный эффект одним ручным действием. Реальный импорт, Transform и воспроизведение требуют проверки в установленном QP2.

QP2 UI обычно исчезает во время Play/Run — это не доказательство, что плагин отключён. Структура QP2 и графы должны сохраняться: нельзя просто превратить такое дерево в набор обычных ParticleEmitter. Положительный структурный результат инспектора не доказывает совместимость runtime, происхождение, право использования или внешний вид.

Скриптовые события могут требовать доверия с правами плагина. Агент не должен автоматически нажимать Trust Script / Trust Asset / Allow или обходить защиту ради предпросмотра. Установка, обновление, публикация и загрузка ассетов в аккаунт не выполняются этим навыком автоматически.

## Лицензии
В Elio включены только наши инструкции и наш инспектор. Сам плагин QP2, Part_Icles, каталог эффектов, ключи и аккаунтные данные не включены. Публичная документация не даёт права распространять чужой движок. Лицензия публичного runtime требует указания Qwinkle в коммерческих играх; отдельно проверяйте условия конкретного ассета и установленной версии.

## Сборка и проверка
Это полные **исходники для существующей GitHub Actions сборки Windows**, не новый Windows EXE и не альтернативный установщик. Обновлять нужно приложение и соответствующее расширение из одной сборки.

В QP2-TEST-RESULTS.json записаны результаты проверок. Реальный локальный API агента проверяется в отдельной временной конфигурации: авторизация, миграция, маршрутизация, полный доступ к ресурсам из упакованного расширения и запрет выхода за каталог. Тесты Luau используют искусственное дерево DataModel, а не установленный QP2. Linux debug build не заменяет Windows-сборку и живую проверку плагина.

Позднее проверяем оба плагина одинаково:
1. Найти открытый плагин в Edit по свежему пути; отдельно проверить поведение после Play → Stop.
2. Вставить/Transform один разрешённый эффект, подтвердить фактический новый объект в Studio.
3. Прочитать структуру и ссылки, проверить установленный runtime без автоматического доверия к событиям.
4. Запустить короткий безопасный preview; проверить вид, свежие ошибки и остановку без повреждения других эффектов.

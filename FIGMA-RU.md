# Elio 1.0.1 · Figma UI & Icons

## Что добавлено

Раздел **Figma** в приложении и команда **elio_figma** у агента. В текущей реализации используется собственный локальный плагин **Elio Link**, работающий через официальный Figma Plugin API. Это не официальный Figma MCP и не маскировка Elio под Codex.

Можно:
- читать выделение или конкретный node_id и структуру текущей страницы, в ограниченном объёме;
- создавать редактируемые FRAME, COMPONENT, RECTANGLE, ELLIPSE и TEXT;
- настраивать Auto Layout, размеры, отступы, цвета, обводку, скругление и типографику;
- создавать редактируемые векторные иконки из статического SVG;
- дорабатывать собственный дизайн по стабильному build_id, заменяя его целиком;
- экспортировать узел в SVG/PNG, просмотреть и скачать экспорт в разделе Figma.

Перенос в Roblox не добавлялся. Figma-команды не требуют открытой Roblox Studio.

## Подключение — один раз импортировать, затем запускать в нужном файле

1. Собрать новую версию **через существующий GitHub Actions**, как обычно. Встроенный Build-Windows.ps1 запускает тесты и упаковку автоматически. Локальная сборка пользователю не требуется.
2. Запустить новый Elio и перезагрузить расширение из обновлённой папки elio-Extension.
3. Открыть **Elio → Figma → Download Figma plugin**. Распаковать ZIP в постоянную папку. Та же папка `figma-plugin` уже включена в Windows-архив.
4. В **Figma Desktop** открыть Plugins → Development → Import plugin from manifest; выбрать `manifest.json` из этой папки. Это локальный development plugin, не опубликованный Community-плагин. Если ваша версия Figma потребует ID, выданный вашему аккаунту, создайте пустой плагин через Development → New plugin и сохраните выданный id в нашем manifest.json; не используйте ID чужого опубликованного плагина.
5. Открыть редактируемый черновик/копию нужного Design-файла и запустить **Elio Link — UI & Icons**.
6. В Elio нажать **Generate pairing code**. Вставить код в плагин и нажать **Connect**. Код не нужно отправлять в чат.
7. Для записи включить **Allow edits** в окне плагина. Держать его открытым. При смене страницы переподключить плагин.
8. Начать новый агентский сеанс или обновить список команд, если открытый сеанс ещё не видел `elio_figma`.

Для проверки соединения есть **Create test card in Figma**. Эта кнопка действительно создаёт тестовый дизайн в подключённой странице; она не запускается автоматически. Повторный тест заменяет только прежний Elio demo build.

Пример запроса агенту:
> В подключённом Figma-файле создай красивый тёмный экран инвентаря: сетка предметов, фильтры и карточка выбранного предмета. Используй Auto Layout и сделай набор собственных векторных иконок. Сначала прочитай страницу. Не меняй чужие элементы и ничего не переносить в Roblox.

Права аккаунта Figma, доступ на редактирование, политика организации по локальным плагинам, доступные шрифты и ограничения текущего плана продолжают действовать. Плагин не обходит их. Если организация запрещает development plugins, потребуется согласование с её администратором.

## Что выяснено об официальном MCP

| Способ | Что даёт | Решение для этой версии |
|---|---|---|
| Remote `https://mcp.figma.com/mcp` | Чтение; у поддерживаемых клиентов — write to canvas через use_figma | Не заявляется подключённым: Figma принимает только одобренные клиенты; новый клиент должен пройти регистрацию/waitlist |
| Desktop MCP Figma | Контекст макета/выделения для поддерживаемых клиентов | Не решает задачу создания: официальная документация исключает canvas write |
| Локальный Figma-плагин | Native Plugin API внутри открытого файла | Реализован собственный Elio Link с ограниченными структурированными командами |

Официальный MCP действительно поддерживает Codex. По документации Write to canvas доступен на Professional/Education/Organization/Enterprise, требует edit access и поддерживаемый remote MCP client; beta может стать usage-based платной функцией. Эти условия относятся к официальному MCP, а не являются обещанием работы Elio Link на любом плане.

## Протокол для агента

`elio_figma` поддерживает `status`, `read`, `apply`, `export`, `result`. Полная схема автоматически попадает в список инструментов; её также описывает `core/figma.js`.

- Сначала status, затем read с уникальным request_id. Это асинхронная команда: получить результат через result с тем же request_id.
- apply: build_id и полный массив 1–120 узлов, максимум 300 KB JSON. Первый узел — FRAME/COMPONENT без parent, остальные ссылаются на более ранний FRAME/COMPONENT. Идентификаторы стабильные, названия понятные.
- Размеры/отступы — в пикселях, цвета `#RRGGBB` или `#RRGGBBAA`. Шрифт по умолчанию Inter. Недоступный шрифт возвращает ошибку до создания слоёв.
- Результат queued/running не означает, что дизайн создан. Успех подтверждает только succeeded с фактическими node_id от плагина.
- При неизвестном результате сначала читать файл. Нельзя повторять потенциально выполненную мутацию с новым request_id.
- У запроса сохраняется fingerprint; повторная доставка идентичного запроса не создаёт второй дизайн. Повторный request_id с другим содержимым отклоняется в пределах сохранённых квитанций.
- В живой сессии хранятся последние 32 запроса. Ключ и очередь не сохраняются на диск, теряются при перезапуске Elio; перед продолжением нужно прочитать файл. На корневом слое сохраняется квитанция последнего apply.
- read возвращает ограниченную структуру/текст/стили. Большие файлы нужно читать адресно по node_id. Это не полный снимок всех свойств или всей библиотеки.
- export требует node_id, формат SVG/PNG, максимум 1 MB. В чат возвращается компактное указание на экспорт; сам файл доступен через раздел Figma, чтобы не отправлять мегабайты base64 в контекст ИИ.

## Сохранность и безопасность

- Плагин общается только с `127.0.0.1:3000/figma-link`. Figma OAuth/PAT, пароли и основной pairing key Elio ему не нужны.
- Отдельный случайный код живёт до 4 часов или до перезапуска/revoke. Он даёт доступ только к poll/result стороне плагина, а не к основным API Elio.
- Только пользователь в приложении выдаёт/отзывает код; агенту эти действия не разрешены. По умолчанию plugin edits отключены.
- Сессия привязана к одному экземпляру плагина. Для смены файла закрыть старое подключение и выдать новый код.
- apply заменяет только корень с совпадающей Elio build ownership-меткой. Остальные верхнеуровневые слои не удаляются. Если внутри корня найдены слои без метки Elio, замена отклоняется.
- Новая версия сначала собирается как staging-дерево. При ошибке оно удаляется, предыдущий корень остаётся. Это защита на уровне Plugin API, не обещание ACID-транзакции при аварийном закрытии Figma в середине выполнения.
- Произвольный JavaScript/eval, команды ОС, удалённые изображения и SVG со скриптами/ссылками не поддерживаются.
- Revoke не способен отменить действие, уже выполняющееся в Figma. Перед повтором проверить файл. Для важного дизайна использовать draft/дубликат и штатную историю Figma.

## Ограничения этой версии

Это ограниченный design bridge, а не вся Plugin API и не копия возможностей official use_figma. Пока нет variables/styles API, библиотечных импортов, variants, raster generation, прототипных переходов и команд удаления произвольных пользовательских узлов. Правки выполняются полной заменой своего build, не точечным patch. Для больших экранов можно создавать отдельные owned builds по секциям, максимум 120 узлов каждый.

Слои редактируемые и SVG-иконки становятся нативными векторными элементами, но наличие успешной квитанции не доказывает красивую композицию. Нужны просмотр в Figma и итерации дизайна. Здесь не проводился реальный вход в Figma и визуальная проверка макета на её canvas.

## Проверки

`test-figma.cjs` — контрактный симулятор Plugin API: native node mapping, Auto Layout, components/text/SVG, загрузка шрифтов до изменения, rollback, сохранение чужих слоёв, idempotency, отказ опасных SVG, чтение/экспорт, загрузка раздела, схема/паритет расширения, работа команды без Studio.

`test-figma-live.cjs` — настоящий Rust HTTP backend + настоящий Chromium, но Figma worker симулирован: отдельный ключ, отказ основного API плагинному ключу, origin/CORS/private network, read-only gate, once-only delivery, повтор ACK, очередь/результат/export, совпадение встроенного плагина, загрузка ZIP с проверкой CRC, раздел приложения, demo/result/preview/download, узкое окно и revoke.

Rust: **144 passed, 0 failed, 1 ignored** (3 library + 141 binary). Прошли **14 выбранных JS-регрессий**, отдельный Figma HTTP/UI-прогон и существующие браузерные прогоны чата и памяти.

При обновлении Elio обновляйте и файлы development plugin в его постоянной папке либо импортируйте новый manifest заново: Figma не обновляет локальный плагин из Community автоматически.

Повторно проверены встроенный чат и память на реальном backend. Итог — в `FIGMA-TEST-RESULTS.json`. Старый `VAULT-TEST-RESULTS.json` сохранён как отчёт предыдущей поставки, не как новый полный прогон всех JS-тестов.

**Что нужно проверить пользователю после GitHub-сборки:** импорт development plugin в реальном Figma Desktop; локальное разрешение сети, если его запросит Figma/ОС; создание тестовой карточки; реальные шрифты и Auto Layout; второй apply и сохранность чужих слоёв; SVG/PNG экспорт; работу запроса из установленного расширения. Windows/WebView2 и реальный Figma canvas здесь не были доступны для acceptance-теста.

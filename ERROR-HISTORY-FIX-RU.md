# Elio 1.0.1 — ошибки инструментов и карточки истории

## Исправлено

1. **Исключение инструмента больше не завершает весь цикл агента.** Оно превращается в `ERROR`-результат с исходным сообщением и передаётся модели для диагностики. Неправильный тип результата тоже обрабатывается, вместо падения на `feedback.includes()`.
2. **Неудачная команда не повторяется автоматически.** При неизвестном/частичном результате агенту предписано сначала проверить состояние. Stop и отмена отправки остаются остановкой, а не поводом продолжать работу.
3. **Карточки Notion привязаны к сообщению и чату, а не к переиспользованному DOM-элементу.** Старый error/done не наследуется следующей командой с таким же именем. Удалена возможность забрать чужую карточку только по давности и имени инструмента.
4. **Обычная перерисовка того же сообщения сохраняет его итог.** При смене сообщения/роли очищаются только принадлежащие расширению ссылки и атрибуты; текст истории и дочерние элементы Notion не переписываются.
5. **Итог инструмента закрепляется за ответом, захваченным до выполнения**, а не за последним ответом, появившимся к моменту окончания.

## Проверки

- До исправления тесты воспроизводили необработанное исключение инструмента и четыре нарушения владения карточками.
- `test-tool-error-recovery.js`: исключения, следующий вызов после ошибки, отсутствие повтора, отмена, неправильный результат, синхронный throw, захват владельца до выполнения.
- `test-notion-card-ownership.js`: 11 сценариев — переиспользование DOM, lookup/sync, другой чат/сообщение, одинаковые команды, перерисовка того же ответа, обычный текст и маска результата.
- `test-stop.js`: Immediate/Safe Stop и ожидание завершения уже отправленной операции.
- `test-message-error-preservation.js`: 566 существующих функций вне исправляемых участков не изменены относительно предыдущего полного исходника.
- `test-notion-card-browser.cjs`: реальный Chromium, CSS-карточка ошибки остаётся на старом сообщении, следующая команда получает отдельную карточку выполнения.
- Новые основные тесты добавлены в `Build-Windows.ps1`.

## Установка

Это **полный исходник** для прежнего GitHub Actions workflow. Запустить **Build Windows → Run workflow**, установить полученный Windows-артефакт и обновить расширение из него, затем перезагрузить вкладку чата.

Предыдущая автоматизация Studio, `studio_ui_snapshot` / `studio_ui_action`, разрешения Full PC, проверки безопасности и `core/config.js` сохранены. Версия продукта остаётся **1.0.1**; идентификатор исходника обновлён.

Исправления относятся к воспроизведённым причинам; для сопоставления с конкретным сбоем пользователя по-прежнему полезны название чата и текст ошибки.

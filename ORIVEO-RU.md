# Oriveo в Elio 1.0.1

Добавлен браузерный провайдер **Oriveo**: https://app.oriveoai.com/chat.
Сборка — через GitHub Actions, как раньше. Отдельный способ сборки не добавлялся.

## Что подключено

- Oriveo в списке поддерживаемых ИИ приложения и расширения.
- Загрузка адаптера на точном домене `app.oriveoai.com`; получение статусов моста.
- Отправка текста через настоящий composer и его кнопку Send. Никаких запросов к скрытому API сайта или сохранения API-ключей.
- Чтение пользовательских и ответных сообщений, стабильные идентификаторы, абзацы, кириллица, fenced JSON/Luau, совместимость с общим парсером команд Elio.
- Отслеживание генерации по Stop generating / индикатору Generating, обработка нативного Stop.
- Исключение служебных кнопок, названий моделей и скрытых копий мобильного интерфейса из текста ответа.
- Защита черновика: существующий неотправленный текст не перезаписывается. Неопределённый результат отправки не вызывает повторную отправку.
- Память проекта и Figma bridge из предыдущей версии сохранены. Провайдер использует общий движок Elio, а не отдельную реализацию инструментов.

## Проверено

Адаптер изучен и проверен на живом сайте. Сначала через интерфейс получен ответ с двумя абзацами, кириллицей и JSON-блоком. Затем сам новый адаптер отправил отдельный короткий запрос, увидел начало генерации и прочитал конечный ответ `Adapter OK — Кириллица 🐔`. В чате наблюдалось ровно два запроса и два ответа. Этот тест не запускал команды в Roblox и не изменял документы Figma.

`test-oriveo.cjs` проверяет сохранённый реальный DOM и имитированные переходы состояния: 23 проверки, включая общий парсер, единственную отправку, неоднозначное подтверждение, заблокированную кнопку, черновики, фильтрацию ролей, регистрацию и совпадение двух копий расширения. Тест добавлен в существующий GitHub/Windows build script.

## Ограничения

- Проверен текстовый чат. Автоматическая отправка изображений/файлов в Oriveo в этом адаптере **не поддерживается**. В выбранной при проверке модели кнопка изображений была отключена. Elio не пытается выдать скрытое поле загрузки документов за поддержку зрения.
- Доступность моделей, ограничения бесплатного аккаунта и необходимость входа определяет Oriveo. Автоматического обхода ограничений нет.
- Внешний сайт может изменить DOM; тогда адаптер должен сообщить о недоступном поле/отправке, а не нажимать посторонние кнопки.
- Полная цепочка установленного расширения → Oriveo → локальная Windows-программа → Roblox/Figma пока не проверялась в новой сборке. Выполнены живые проверки адаптера, автоматические тесты исходников и нативные Rust-тесты под Linux, не Windows/WebView2.

Результаты и границы проверки: `ORIVEO-TEST-RESULTS.json`.

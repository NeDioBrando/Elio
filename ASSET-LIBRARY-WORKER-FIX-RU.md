# Исправление загрузки встроенной библиотеки Elio

## Причина
В классическом service worker Manifest V3 первый importScripts из обработчика инструмента выполнялся после установки worker. Chrome блокировал загрузку даже при наличии core/asset-library.js. Ошибка воспроизведена в настоящем Chromium до изменения кода.

## Исправление
- Библиотека синхронно подключается при начальном выполнении background.js.
- Каталог JSON по-прежнему читается лениво, локально и кешируется; общие одновременные запросы используют одну загрузку.
- Сбой библиотеки не останавливает остальной background worker. Ответ library_unavailable содержит причину, путь ресурса и инструкцию восстановления.
- Зеркальная папка elio-Extension обновлена вместе с корневыми исходниками.

## Проверки
- Реальный Chrome MV3: stats (5515 записей), search, get, guide, исходный запрос из отчёта, повторный запуск worker, зеркало расширения, отсутствующий JS-файл.
- Ошибка чтения каталога и повторная попытка; восемь одновременных запросов используют один кешированный каталог; поздних importScripts нет.
- Регрессии библиотеки, полного аудита, ошибок инструментов, Stop, идентичности, упаковки и Studio desktop contract прошли.
- Браузерная регрессия добавлена в Build-Windows.ps1.

## Обновление
Замените целиком папку elio-Extension из новой Windows-сборки. В chrome://extensions нажмите «Обновить» на карточке Elio, затем перезагрузите вкладку Notion. Если расширение загружается из другой папки, укажите новую папку через «Загрузить распакованное расширение». Full PC access для библиотеки не требуется.

Поиск использует пересечение ключевых слов: отсутствие результатов на длинный запрос — не сбой загрузки. Для подбора ассетов используйте отдельные запросы beam, lightning, spark.

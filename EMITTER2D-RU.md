# Emitter2D и отмена разовых подтверждений

## Что изменено
- Удалён добавленный в предыдущем переносе механизм разовых подтверждений непрозрачного Luau/shell и удаления. Больше нет кнопки Allow once, ожидающей заявки или срока в две минуты.
- Старый `confirm_deletions: true` в `%LOCALAPPDATA%/elio/safety.json` игнорируется: ручное удаление настроек не требуется. Read-only и allowed_folders сохраняются, включая старые пользовательские значения. Повреждённая политика по-прежнему включает read-only, а не снимает ограничения.
- Сохранены защита отмеченных путей, резервные копии/checkpoints, режим чтения, ограничения папок, запрет выхода из workspace, проверки доверия к импортированному коду и обычные разрешения плагинов. Это не отключение всей защиты компьютера.
- Ошибка доступа больше не выдаётся за ошибку синтаксиса Lua и не предлагает переписать команду для обхода ограничения. Совместимость со старым агентом не превращает его блокировку в автоматический повтор.
- Исправлено обнаружение плагинов: существующие read-only plugin_list/plugin_inspect теперь попадают в каталог Roblox, доступны запросу схемы и передают указанный Studio ID в execute_luau. Они не рекламируются в локальном движке. Не включён весь старый набор мутирующих virtual tools.

## Emitter2D — Gui Particles
Встроен включённый базовый навык `builtin-emitter2d` для плагина dogwarrior24, Creator Store 9544897050. Применяется к явному запросу Emitter2D и Roblox UI/GUI/HUD-частицам/конфетти. Обычные 3D VFX, Eclipse, web CSS и явно выбранные QP2/VFX Studio не подменяются этим навыком. Отключение/удаление пользователем сохраняется при перезапуске.

В составе: инструкция, рабочий процесс, публичный контракт атрибутов и четырёх дочерних BindableEvents, источники и ограниченный read-only Luau-инспектор экспортированных объектов. Инспектор не читает Source, не выполняет модули/события, не меняет атрибуты и не копирует частную библиотеку. Он сообщает фактические типы атрибутов: сериализация диапазонов/последовательностей не выдумывается. Неполная проверка никогда не объявляет объект готовым.

Это интеграция рабочего процесса через установленный плагин, **не новый скрытый API управления его кнопками**. plugin_list/plugin_inspect читают доступный UI; они не нажимают Create/Convert/Install Client. Если разрешённого управления Studio UI нет, агент попросит одно конкретное ручное действие. Сторонний плагин, клиент и ассеты не включены в ZIP и автоматически не устанавливаются.

Публичная документация требует Install Client для игры и после обновления плагина. Разрешение на установку/внедрение скриптов остаётся за пользователем. Автор сообщает несовместимость с Server Authority/Next Generation Replication; Elio не отключает эту настройку. Актуальная сериализация и совместимость устанавливаются по реально установленной версии.

Источники: https://create.roblox.com/store/asset/9544897050/Emitter2D и https://devforum.roblox.com/t/3742009

## Как обновить и проверить
Используйте этот полный исходный архив в обычной GitHub Actions сборке. Локальный Windows EXE здесь не собирался. Обновите приложение и соответствующее расширение, перезапустите их и обновите вкладку чата — уже запущенная старая версия не меняется от патча исходников.

Затем в настоящем Studio проверяем обнаружение VFX Studio/QP2/Emitter2D, реальный экспорт, client preview и очистку. Эти операции и визуальный результат не подтверждены тестами в Linux. Eclipse не переписывался.

Точные результаты текущего запуска — EMITTER2D-TEST-RESULTS.json. Старые отчёты описывают предыдущие версии; сведения о разовых подтверждениях в них устарели.

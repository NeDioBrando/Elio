# Fast workflow
1. Read the brief and existing GUI/controller. Confirm Edit/Play state and connected Studio. Inspect only relevant roots and current selection. Do not create an unrelated UI redesign.
2. Discover fresh accessible plugin UI with advertised plugin_list/plugin_inspect; inspect visible/enabled controls and screenshots before authorized desktop input. These tools do not query a private library or click. If no desktop control exists, ask the user to open Emitter2D and perform one concrete action.
3. The documented toolbar provides Create Emitter under the selected GUI and Convert Emitter for selected native ParticleEmitters. Conversion leaves a GUI emitter beneath the original 3D emitter; move only the new owned export into the intended GUI after inspection. Preserve the 3D original. Do not invent these as Luau APIs. Snapshot the relevant target before insertion and compare actual after-state.
4. Install Client is required for in-game behavior, including after plugin updates. Ask before installation, script injection permission or replacing any runtime. Read unknown scripts separately before execution. Do not infer a runtime path from its name, invoke require to discover an API, or silently change Server Authority.
5. Inspect exact exported roots with scripts/inspect_emitter.luau, for example prepend local SPEC={paths={"game.StarterGui.MyHud"},max_nodes=160}. Selection requires use_selection=true and must not be combined with paths. Inspect runtime/client PlayerGui with normal advertised tools in the actual Client DataModel; this bounded Edit/export inspector intentionally excludes Players/private services.
6. Tune only owned objects after observing actual attribute types and installed version. Use plugin UI where serialization is unknown. For a requested new complete Roblox UI, retain the normal creation_preview/saved-revision insertion workflow; do not rebuild it independently in Luau.
7. Inspect actual existing BindableEvents and client runtime. With authorized preview, invoke only the documented emitter child events in the Client context, with small bounded counts/duration. Preview does not grant permission to run unknown event code. Stop and clean owned preview objects; do not Clear another user's active emitter or disable shared clients.
8. Check mobile size, clipping, ZIndex, burst rate, lifetime, cancellation and fresh errors. No visual/runtime success claim from inventory alone. Save verified reusable paths/version/evidence only when memory is enabled; avoid entire catalogs.

# Обновления Elio 1.0.1

## Что видит пользователь

В нативном приложении и поверх поддерживаемой страницы ИИ появляется заметная панель **Версия устарела · Outdated**, установленная/доступная версия и кнопка **Обновить**. Такая же панель есть в popup расширения. На странице ИИ она не зависит от того, запущен ли агент и показана ли его основная панель.

Все три интерфейса используют один локальный сервис обновлений. После нажатия отображаются загрузка, процент и установка; повторный запуск блокируется. Проверка выполняется при старте и затем каждые четыре часа. Проверка не устанавливает обновление без нажатия. При отсутствии связи с GitHub появляется ошибка и **Проверить снова**, а не ложное «актуально».

Установка не должна прерывать работу: остановите задачи ИИ во всех браузерах и дождитесь окончания инструментов. Пока идёт установка, новые изменяющие команды блокируются. Roblox Studio и Blender помощник не завершает. Приложение перезапускается. После замены файлов расширения панель просит **Перезагрузить расширение**, затем обновить открытые вкладки ИИ. Это не обновление через Chrome Web Store.

## Текущая версия исходников — **Elio 1.0.1**, тег — **v1.0.1**, установочный файл — **elio-v1.0.1-Windows-x64.zip**. Сначала получите успешную Windows-сборку и проверьте её, затем публикуйте новый неизменяемый тег. Не перезаписывайте уже существующий релиз. Распакуйте готовый ZIP в отдельную папку, запустите **elio.exe** и загрузите установленную папку `elio-Extension` в Chromium. ZIP исходников не содержит EXE.

Эта версия ещё не опубликована. Первый новый пакет устанавливайте вручную вместе с расширением из того же ZIP. Старые идентификаторы продукта, хранилища и pairing-файлов заменены, автоматическая миграция прежних установок не заявляется.

Архив исходников **не содержит Windows EXE**. При совпадении установленной и опубликованной версии 1.0.1 надпись Outdated не появляется; она появится после публикации более новой стабильной версии. Тег `v1` без полного номера не принимается.

Для первого выпуска после проверки сборки используйте `v1.0.1`. Ниже приведены команды этого выпуска; для последующего выберите новый номер, например 1.0.2.

## Как выпускать следующую версию

Исходники остаются в main. Пользователь скачивает из Releases **готовый Windows ZIP**, не автоматически созданные GitHub архивы Source code.

1. Внесите изменения. Из корня репозитория выполните:

```powershell
python tools/set_version.py 1.0.1
git add .
git commit -m "Release 1.0.1"
git push origin main
```

2. Сначала запустите **Actions → Build and release Elio (Windows x64) → Run workflow**. Скачайте artifact `Elio-Windows-x64`. Проверьте сборку и реальный переход со старой версии на новой тестовой установке Windows, включая ошибку запуска/восстановление и перезагрузку расширения. Автоматические тесты — не замена этому прогону.
3. После проверки отправьте **новый, ранее не использованный** тег:

```powershell
git tag v1.0.1
git push origin v1.0.1
```

4. Тег запускает Windows-сборку и тесты. Workflow создаёт draft с готовым `elio-v1.0.1-Windows-x64.zip`, затем публикует stable Release и отмечает Latest. При ошибке публикации проверьте оставшийся draft. Не создавайте заранее Release с тем же тегом: workflow не перезаписывает существующий релиз.
5. Не меняйте уже опубликованный ZIP. Исправление — новая версия и новый тег. Версии сравниваются численно: 1.0.10 новее 1.0.9. Принимаются только стабильные `X.Y.Z` и теги `vX.Y.Z`, не prerelease.

Репозиторий должен разрешать Actions и запись Releases через GITHUB_TOKEN. Автопубликация происходит при push тега, не при обычном коммите в main. `Run workflow` только собирает artifact, не публикует релиз.

Можно опубликовать релиз вручную вместо tag-workflow, но ему нужен ровно один asset с точным именем `elio-vX.Y.Z-Windows-x64.zip`, тегом `vX.Y.Z`, совпадающими внутренними версиями и флагом Latest. GitHub API должен вернуть для asset поле `digest: sha256:...`; без него установка откажет. Не прикладывайте существующий старый ZIP под новым номером.

## Устройство и границы доверия

- Единственный источник — `NeDioBrando/Elio`, API `releases/latest`. Приложение не принимает произвольные адреса скачивания, команды, репозиторий или путь установки из интерфейса.
- Защищённые существующей авторизацией моста маршруты: `GET /api/updates/status`, `POST /api/updates/check`, `POST /api/updates/install`. Расширение обращается через background; секрет моста не вставляется в DOM сайта.
- Загрузка только HTTPS, разрешённые хосты GitHub, ограничения размера. Проверяются размер и SHA-256 из API GitHub. Перед установкой метаданные должны быть не старше 15 минут; иначе установка откажет и предложит повторить проверку.
- **Отдельной цифровой подписи пакета/Ed25519 и Authenticode здесь нет.** SHA-256 из того же GitHub не защищает от захвата аккаунта/репозитория. Защитите аккаунт и публикацию релизов. Это граница доверия текущей реализации, а не независимая подписанная цепочка обновления.
- Локальный встроенный помощник PowerShell повторно проверяет SHA-256, ZIP-пути, дубликаты, ссылки, размер распаковки, ожидаемую структуру, manifest и `exe --version`. Из сети скрипт установщика не скачивается. Архив содержит корневую папку `elio`.
- Только после подготовки пакета помощник разрешает старому приложению выйти. Он ждёт завершения именно его PID, создаёт резервные копии управляемых файлов, заменяет их, запускает новый процесс и ждёт подтверждения открытия портов моста и краткой проверки живого процесса. Это не проверка полной готовности GUI, Roblox или Blender.
- При ошибке выполняется **попытка отката** и запуска прежнего EXE. Восстановление не гарантируется при блокировке файлов/сбое диска; детали и backup сохраняются в `%LOCALAPPDATA%\elio\updates\stage-*`. Файлы пользователя вроде config.json, userdata, logs, workspace не являются целями замены. Устаревшие управляемые файлы, которых больше нет в новом ZIP, сейчас не удаляются.
- Система не запрашивает повышение прав, не отключает защиту ОС и не снимает ограничения политики организации. Папка установки должна быть доступна пользователю на запись; Windows PowerShell должен разрешать запуск локального помощника.

## Ограничения

Автоматическая установка рассчитана на Windows x64 и Chromium-расширение, загруженное из установленной папки. Не добавлен канал обновлений магазина расширений. Lightpanda пока не подключена: UI получает независимый статус через локальный мост, но будущему браузерному адаптеру понадобится собственный transport вместо chrome.runtime. Обновления Chromium, WebView2, Roblox Studio, Blender и MCP-зависимостей этим механизмом не управляются.

В Linux-среде разработки Windows EXE не собирался и обновление Windows не выполнялось. До распространения обязательна Windows-проверка. Перечень реальных тестов: UPDATES-TEST-REPORT.md.

## После переименования репозитория

Метаданные и точные URL загрузки привязаны к `NeDioBrando/Elio`. Проверка SHA-256, версии, списка файлов и rollback не отключены. Переименование на GitHub не меняет уже собранный старый EXE: первую новую сборку при необходимости установите вручную. Новые сборки обращаются непосредственно к адресу Elio.

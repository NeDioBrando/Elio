# Authoring, Inventory and structure
Read the actual current installed UI. Documentation labels can drift. Installation and upgrade are separate user-authorized work, not part of adding this Elio skill. Online/trial/license state can explain unavailable panels; report observations rather than disabling checks. Local Inventory upload can upload files to the user's Roblox account: not a local-only edit, requires approval. Do not bundle any downloaded catalog.

QP2 Transform creates a PartIcleProperties Configuration and RenderTemplate; the original becomes an emitter, often invisible. Keep its graph/range attributes and visual template. Inspect actual current exported structure; missing required RenderTemplate can cause runtime no-op rather than an error. EmitCount 0 with EmitDuration 0 can also explain a no-op. Check values before diagnosing a transport failure. Older format should be upgraded only through the observed plugin flow with approval/backup, not by guessing attributes.

Graph life-axis is normalized 0..1, not seconds. Existing live particles generally keep settings taken at birth. Native properties, graph-encoded attributes and UI representations are not interchangeable. Use plugin panel / current generated code when encoding is not documented; do not invent a JSON graph schema. GraphBlender, MeshFlipbooks/BeamFlipbooks/TrailFlipbooks/ImageFlipbooks/MeshFrames and nested RenderTemplates must travel together.

Link, EmitParent, AccelTarget, ShapePart are ObjectValue references. Confirm whether targets stay inside the copied export; external links must be deliberate, not rewired to unrelated objects. Template clones can themselves contain nested emitters. Avoid double-emitting a parent and its children through a recursive call.

Inventory has textures, flipbooks and effect assets; their insertion has different results. A thumbnail ID is not an entire effect model ID. plugin_inspect query only searches the accessible materialized UI tree; actual remote Inventory search requires observed authorized UI input. Never claim a full catalog search from a scan of loaded labels. Compare selected objects and destination before/after UI acquisition, then use exact resulting paths.

Events inside PartIcleProperties can call ModuleScripts. Inventory events may arrive untrusted/off and the plugin can ask to allow scripts for the place. Those are security controls, not bugs to toggle around. The inspector flags scripts/events/external references but does not prove that their absence means safe execution. Even an existing runtime module must be reviewed with normal source-reading tools.

For joint QP2/VFX Studio debugging, keep separate evidence rows: live state; discovery warnings; exact UI/library action; resulting source path; structure/script/reference hazards; runtime/module version; preview result; cleanup. Failure in one row is not proof all later operations failed. Test one bounded item per plugin on separate owned sources; never run destructive Forces/Reactors as a generic smoke test.


## Same-name plugin windows
Read fresh plugin_list output. Pass both exact path_segments and its surface_title to plugin_inspect when provided. Several widgets can share Name=PluginGui; name segments alone do not distinguish them. Titles are exact and case-sensitive, not fuzzy search. Stale or still-duplicate titles must fail closed: rediscover, never choose the first sibling, rename user/plugin objects, or assume a missing path means uninstalled. Nested same-name controls remain ambiguous; use a narrower unambiguous parent. No click/import is performed.

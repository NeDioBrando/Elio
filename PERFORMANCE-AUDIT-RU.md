# Elio 1.0.1 — аудит памяти, ресурсов и производительности

## Результат и границы
В исходниках исправлены воспроизведённые утечки и ошибки жизненного цикла, добавлены ограничения на неограниченно растущие буферы и ускорено объединение истории. Версия продукта остаётся 1.0.1. Существующий GitHub Actions / Build-Windows.ps1 сохранён; добавлен тест ресурсов, а не новая система сборки.

Это не сертификат отсутствия любых утечек. Проверки выполнены на Linux, с настоящим локальным агентом и headless Chromium, но без настоящей Windows/WebView2, пользовательских провайдеров, Studio, Blender и Figma. Полная Windows-сборка и многочасовой тест на пользовательском ПК остаются обязательными.

## Что было исправлено

### Интерфейс
- Локализация удерживала удалённые деревья DOM через сильные ссылки в реестрах. Теперь удалённые владельцы, переводы, переключатели языка и наблюдатели освобождаются; повторное подключение не теряет исходный английский текст. Документный наблюдатель не пересканирует все переводы при каждом стороннем DOM-изменении.
- Реестр кнопок темы использует слабые ссылки вместо удержания закрытых кнопок.
- Повторное открытие Skills уничтожает предыдущий экземпляр, таймеры и подписку локализации; запоздавший ответ не перерисовывает новый интерфейс.
- Закрытый Creator preview больше не возрождает polling/render timers после асинхронного ответа и освобождает свои данные. Завершение уже отправленной команды при закрытии не выдаётся за отмену: перед повтором нужно проверить результат.
- Раннее пробуждение ожидания очищает исходный timeout; 1000 пробуждений не оставляют 1000 таймеров.
- Изменения core синхронизированы с расширением.

### Агент и мост
- Очередь Studio ограничена 32 запросами и 8 MiB сериализованных данных. При заполнении отклоняется НОВЫЙ запрос с явной ошибкой; старые команды не вытесняются.
- Legacy WebSocket: максимум 32 исходящих кадра и 64 MiB суммарных удерживаемых данных, включая отправляемый кадр; timeout записи 10 секунд. Медленный клиент закрывается вместо накопления буфера. Writer и вспомогательные задачи очищаются при отключении.
- До 32 одновременно выполняющихся legacy tool calls глобально. Уже начатая команда не повторяется и не объявляется отменённой только из-за закрытия вкладки.
- Реестр подключений ограничен 128 клиентами; ID до 256 байт, engine до 32 байт. Существующее подключение не вытесняется новым.
- Обычный results WebSocket переживает broadcast lag, имеет timeout отправки.
- Pending-запросы desktop agent удаляются при отмене HTTP future, успехе и timeout. Защита поколений не даёт старому cleanup удалить новый запрос с таким же ID.

### MCP и диагностика
- Строка MCP stdout ограничена 32 MiB, включая строку без завершающего LF. Чтение сохраняет частичные данные при отмене ожидания; слишком большой ответ вызывает контролируемую ошибку/reset, а не автоматический повтор потенциальной мутации.
- Строка stderr addon ограничена 4000 байт; слишком длинная строка дренируется, следующий вывод продолжает читаться. При Drop addon прерывается его stderr task.
- UI diagnostic ring: максимум 1200 строк по 4000 символов Unicode.
- agent.log: ротация по 5 MiB плюс один backup agent.log.1. Размер контролируется при записи, не только при запуске. Эти ограничения относятся к диагностике, НЕ к проектным файлам или переписке.

### История и память проекта
- Объединение истории индексирует ID через HashMap вместо повторного линейного поиска. Подсчёт байтов и обрезка выполняются без повторного суммирования всей истории. Сохранены порядок, обновление сообщений, Unicode и атомарная запись.
- Внешние Markdown-файлы vault теперь проверяются до массового чтения: суммарно до 64 MiB физических .md и 32 MiB декодированного текста. Это закрывает обход ограничений через ручное копирование файлов. При превышении выдаётся ошибка; файлы НЕ удаляются. Существующие лимиты 5000 заметок, 100000 байт на файл и cache до 8 проектов сохранены.
- Защитные dedup-реестры не очищались вслепую ради экономии памяти: это могло бы повторно выполнить старую мутацию. Живая история и индексы проекта также не считаются утечкой лишь потому, что занимают память.

## Проверки и измерения
Машиночитаемые результаты находятся в PERFORMANCE-AUDIT-RESULTS.json.

- Rust: 165 успешных тестов, 1 ignored, 0 failed; Linux debug build успешен. Имеющиеся compiler warnings не выдаются за отсутствие предупреждений.
- 28 регрессионных команд: identity, rename, чат, desktop chat, темы, обновления, vault, Oriveo, Figma, Eclipse, VFX, протокол, guard, motion, реальные Luau fixtures, 5 Chromium UI suites, packaging и Engram preparation.
- Отдельный VFX Luau inspector: 31 проверка в simulated DataModel, не живой UI плагина.
- Жизненный цикл UI: 18 проверок, 200 удалений переведённых корней, 80 удалений language pickers, 100 remount Skills, запоздавшие ответы, 1000 ранних пробуждений, parity.
- Chromium: 300 удалённых окон по 30 кнопок, одинаковая нагрузка до/после и принудительная GC. Последний замер прироста used JS heap: 3 225 904 → 175 940 байт (примерно 3,23 → 0,18 MB). До исправления retained heap рос на каждом пакете. Это не общий RAM приложения и не прогноз результата на Windows.
- Настоящий агент, изолированная временная папка: 60 секунд до/после, 61 сохранение истории по 1500 сообщений, более 1100 status запросов, 80 reconnect/ping/close; экспорт подтвердил все 1500 сообщений без пропусков.
- Медиана обработки истории в fixture: 52,908 → 44,113 ms, p95 64,747 → 59,202 ms. Это не ускорение генерации ИИ или всего приложения.
- При 64 запросах с крупными payload кандидат принял 20, отказал 44 по байтовому бюджету; FIFO сохранён. Старый агент принял все 64. Команды из очереди не исполнялись.
- Медленный WebSocket-клиент: 300 read-only обращений к временному 512 KiB файлу; ограничение/отключение сработало. Никакие пользовательские файлы не изменялись.
- В candidate добавлена нагрузка медленного клиента, которой нет в baseline: финальные RSS этих двух прогонов НЕЛЬЗЯ напрямую сравнивать как экономию RAM. Короткий прогон не доказывает отсутствие медленной утечки.

## Что проверить на своём ПК
1. Собрать через существующий GitHub Actions и запустить Windows-версию с актуальным расширением.
2. Несколько часов обычного чата и streaming; периодически открывать/закрывать Skills, Creators, Memory и переключать язык/тему. Сравнивать RAM после одинаковых циклов и периодов покоя, а не только пиковые значения.
3. Проверить disconnect/reconnect, Stop, смену вкладок и возвращение после сна. Не должно быть повторного выполнения команд; явная ошибка перегрузки означает отказ нового запроса, не потерю принятого.
4. Проверить реальные Studio/Blender/MCP/Figma/Oriveo сценарии и большие проекты. Локальные fixtures не подтверждают доступность внешнего сервиса или UI конкретного плагина.
5. Убедиться, что история и vault открываются, существующие заметки на месте. При слишком большом vault уменьшить/разделить его вручную после резервной копии, не удалять данные вслепую.

## Комплект
Полные исходники, не патч. Сохранены Memory, Figma, Oriveo, Eclipse Animator, VFX Studio и их документы. Добавлены resource_limits.rs и воспроизводимые audit tests. Baseline для сравнительных тестов задаётся ELIO_AUDIT_BASELINE / ELIO_AUDIT_BASELINE_BINARY; на другом ПК нужен отдельный распакованный предыдущий исходник/бинарник. Test scripts не требуют доступа к пользовательскому Studio. Для текущего комплекта с QP2 хеши файлов находятся в QP2-SOURCE-SHA256SUMS.txt. Измерения этого отчёта относятся к этапу performance audit; актуальные проверки VFX см. VFX-PLUGIN-FIX-RESULTS.json.
